GitOps · AI risk review · self-healing rollback

Push code. Helmsman takes the wheel.

Helmsman reads your repository, writes the Dockerfile and the Kubernetes manifests, has an AI review the blast radius, and commits the result to your GitOps repo. ArgoCD deploys it. Then Helmsman watches the rollout — and reverts the commit itself if the pods don't come up.

Run it in 60 seconds Source
~/my-service 
$ ./bin/pipeline -app-repo . -app checkout-api -env staging \
    -image ghcr.io/acme/checkout-api:sha-9f3c1b

== 1/4 detect ==
  language=node framework=express entrypoint="npm start" port=4000 confidence=high

== 2/4 containerize ==
  wrote ./Dockerfile (multi-stage, non-root, distroless-minded)

== 3/4 generate manifests ==
  deployment.yaml, service.yaml, ingress.yaml, kustomization.yaml
  replicas=3 cpu=150m/750m mem=192Mi/768Mi public=true

== 4/4 risk review + commit ==
  static: 0 findings   ai: 0 findings   score=4/100  approved
  committed a41f0c8 to gitops-repo:apps/checkout-api/staging

ArgoCD will reconcile the commit. health-watcher takes it from here.
The pipeline

Six stages. Only two of them ask an AI anything.

Detection, containerization and manifest generation are deterministic and template-driven, because they are solved problems — a probabilistic answer there is strictly worse than a correct one. The AI is spent where a static rule can't help.

Deterministic — templates and rules AI-assisted — judgment calls only Your existing ArgoCD, untouched
The design decision

The interesting part is how little of this is AI.

Most of the pipeline is boring on purpose. "AI-generated YAML" fails by being subtly invalid or inconsistent between runs — so that failure mode is designed out rather than reviewed for.

Deterministic no model call

templates · marker files · regex
  • Language & framework detectionMarker files and dependency manifests. Node, Python, Go, Java, Ruby, Rust — with the port read from your source when it's explicit.
  • Dockerfile generationPer-language templates: multi-stage where it helps, non-root everywhere, exec-form CMD so SIGTERM actually reaches your process.
  • Kubernetes manifestsDeployment, Service, Ingress, Kustomization — identical bytes for identical input, so the GitOps diff is reviewable.
  • Health evaluation"Is this pod crash-looping" is not a judgment call.

AI-assisted Gemini

contextual judgment · fails closed
  • Risk review of the diffLayered on top of static policy checks — an env var that looks like a plaintext secret, a resource shape that doesn't match the workload, a diff that changes more than a routine deploy should.
  • Root-cause analysisPod statuses and cluster events turned into a plain-English explanation and one concrete next step, for the developer who shipped the change.
  • Additive, never subtractiveAn AI finding can raise the risk score. It can never clear a static finding or lower the score below it.
  • No key, no problemWithout GEMINI_API_KEY the review runs static-only and says so. It never silently passes as "reviewed".
What ships

Seven small binaries and no dependencies.

There is no platform server to run. Helmsman is CLIs that run in your app repos' CI, plus one CronJob in your cluster. The Go module has an empty require block — the whole supply chain is the standard library.

pipeline

Runs detect → containerize → manifest → commit end to end. The one command most repos ever call.

risk-reviewer AI

The PR gate. Exits non-zero when the risk score crosses the threshold, so branch protection can block the merge.

health-watcher AI

Runs in-cluster as a CronJob or ArgoCD PostSync hook. Watches the rollout, explains failures, reverts the commit.

detector

Language, framework, build tool, entrypoint and port — from the working tree, with no configuration.

containerizer

A production-minded Dockerfile per language, and a .dockerignore that keeps your .env out of the image.

manifest-generator

Deployment, Service, Ingress and Kustomization, with probes, limits and a locked-down security context.

gitops-writer

Writes and commits to the GitOps repo, renders the ArgoCD Application, and performs reverts for rollback.

platform.yaml

Optional per-app overrides — replicas, resources, env vars, secret references, public exposure. Every field has a safe default.

examples/sample-app

A working Express service and the exact GitHub Actions workflow an onboarded repo runs. Exercised by CI on every push.

Quickstart

No cluster. No API key. About a minute.

The full pipeline runs locally against a throwaway GitOps repo, so you can read the commit it produces before pointing it at anything real.

1

Clone and build

Go 1.23 or newer. Nothing else to install.

git clone https://github.com/zishaan1911/Helmsman.git
cd Helmsman/gitops-ai-platform
make binaries
2

Run it against the bundled example

One target creates a scratch GitOps repo, runs all four stages, and shows you the commit.

make demo
3

Point it at your own service

Any repo with a package.json, go.mod, requirements.txt, pom.xml, Gemfile or Cargo.toml.

./bin/pipeline \
  -app-repo ../my-service \
  -gitops-repo /tmp/gitops-repo \
  -app my-service \
  -image ghcr.io/acme/my-service:sha-9f3c1b \
  -env staging \
  -gitops-repo-url https://github.com/acme/gitops-repo.git
4

Tune it, if you want to

Drop a platform.yaml next to your code. Every field is optional.

port: 4000
replicas: 3
public: true
resources:
  cpuRequest: "150m"
  memoryRequest: "192Mi"
  cpuLimit: "750m"
  memoryLimit: "768Mi"
env:
  - name: LOG_LEVEL, value: info
  - name: DATABASE_URL, secretRef: my-service-secrets/database-url
The rules it plays by

Nothing here can surprise your cluster.

It never mutates the clusterNo kubectl apply, no API writes, no cluster credentials in CI. Helmsman writes files and makes commits; ArgoCD or Flux does the rest, unmodified.
Rollback is a revert, not a resetThe bad deploy stays in history, so the incident is still reconstructable afterwards. And the rollback itself goes through ArgoCD like any other change.
Re-running changes nothingIdentical input produces byte-identical manifests, and an unchanged run makes no commit. Your GitOps history stays a record of real changes.
Secrets stay in KubernetessecretRef renders as a secretKeyRef — never an inline value. Secret material never enters a manifest, a commit, or an AI prompt.
Zero third-party dependenciesThe module's require block is empty. Nothing between your deploy repo and the Go standard library.
Everything is gated by your existing rulesThe output is a pull request against a Git repo. Whatever branch protection, CODEOWNERS and review policy you already run applies unchanged.
